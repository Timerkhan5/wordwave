# Обзор проекта WordWave и работы с ИИ

## 1) Что это за проект
WordWave — веб-приложение на ASP.NET Core MVC с PostgreSQL (EF Core), где есть:
- обычные MVC-страницы (`Views/*`),
- административный раздел,
- отдельные React/TSX-элементы для admin/ui,
- модуль генерации заданий через LLM.

## 2) Как подключен ИИ в текущей реализации

### Сервер
Ключевой сервис: `Services/LlmTaskGenerator.cs`.

Он:
1. Берёт настройки провайдера и модели из конфигурации/переменных окружения.
2. Поддерживает два варианта провайдера:
   - Ollama локально (`/api/chat`),
   - OpenAI-совместимый API (`/v1/chat/completions`),
   - Deepseek (в OpenAI-стиле или через `/generate` в зависимости от `DEEPSEEK_ENDPOINT_STYLE`).
3. Формирует системный и пользовательский промпты.
4. Требует от модели строгий JSON-массив задач.
5. Пытается безопасно извлечь JSON даже если модель добавила лишний текст.
6. Делает базовую валидацию результата (наличие вопроса, 4 вариантов, границы сложности и индекса правильного ответа).

### API для админки
Контроллер: `Controllers/Admin/AiController.cs`.

Доступ: только роль `admin`.

Эндпоинты:
- `POST /admin/api/ai/generate-and-save`
  - генерирует задачи,
  - сохраняет их в БД,
  - возвращает количество и ID созданных записей.
- `POST /admin/api/ai/test-generate`
  - генерирует задачи,
  - **не** сохраняет в БД,
  - возвращает массив для предпросмотра/диагностики.

Оба эндпоинта ограничивают:
- `count` до диапазона `1..20`,
- `difficulty` до диапазона `1..5`.

### Клиентская часть
Кнопка генерации: `admin/components/GenerateTasksButton.tsx`.

Сейчас UI отправляет `topic` и `count` на `generate-and-save`, после чего показывает сообщение об успехе/ошибке.

## 3) Конфигурация окружения
Текущее описание переменных и режима работы собрано в `docs/ai-integration.md`.

Ключевые переменные:
- Ollama (рекомендуется): `LLM_PROVIDER=ollama`, `OLLAMA_BASEURL`, `OLLAMA_MODEL` (например `deepseek-v3.1:671b-cloud`).
- OpenAI: `OPENAI_API_KEY`, `OPENAI_BASEURL`, `OPENAI_MODEL`, `LLM_PROVIDER=openai`.
- Deepseek: `DEEPSEEK_BASEURL`, `DEEPSEEK_APIKEY`, `DEEPSEEK_MODEL`, `DEEPSEEK_ENDPOINT_STYLE`, `LLM_PROVIDER=deepseek`.

## 4) Сильные стороны текущей интеграции
- Есть role-based защита админ API.
- Есть ограничение числа генерируемых задач (контроль стоимости).
- Есть fallback-логика парсинга JSON-ответов модели.
- Есть тестовый endpoint без записи в БД.
- Провайдер абстрагирован через конфиг (Ollama/OpenAI/Deepseek).

## 5) Риски и технический долг
1. **Нестабильность формата LLM-ответа**
   Даже при строгом промпте модель иногда возвращает “почти JSON”. Нужны дополнительные контрактные проверки.
2. **Нет полноценной preview-first схемы в UI**
   Сейчас основной путь — сразу `generate-and-save`. Это может сохранять неидеальные задания.
3. **Ограниченный набор пользовательских параметров на фронте**
   В UI не прокидывается `difficulty`, хотя API его поддерживает.
4. **Отсутствие отдельного аудита генераций**
   Полезно логировать prompt/version/provider/model, чтобы отслеживать качество и регрессии.
5. **Нет rate limit / quota на админ endpoint**
   Может привести к лишним расходам/нагрузке.

## 6) Практический план улучшений

### Быстрые (1–2 дня)
- Добавить в UI выбор `difficulty` и переключатель “только предпросмотр”.
- Ввести серверную валидацию “качества” задания перед сохранением (минимальная длина текста, уникальность опций, проверка корректного индекса).
- Вынести версию промпта в конфигурацию/константу с журналированием в ответе.

### Средние (3–7 дней)
- Добавить журнал генераций (таблица `AiGenerationLog`).
- Добавить ручной модерационный экран: принять/отклонить/исправить перед публикацией.
- Добавить интеграционные тесты для парсинга и нормализации ответов LLM.

### Дальше
- Метрики качества (доля принятых задач, частота ручных правок).
- A/B вариантов промптов.
- Ограничение запросов (rate limiting) по ролям/пользователям.

## 7) Краткий итог
Интеграция ИИ в проект уже рабочая и практичная: есть защищённый админ API, поддержка двух провайдеров и базовая защита от “плохого JSON”.
Следующий шаг для production-качества — добавить preview/moderation контур, расширенную валидацию и аудит генераций.
